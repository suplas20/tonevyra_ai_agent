## 1. Purpose

The purpose of this document is to correct the role of the Lightroom Classic plugin in T-019.

The previous implementation direction allowed or implied that the Lightroom plugin itself could monitor the image input folder and automatically start image work. That direction is incorrect for Tonevyra AI.

The corrected design is:

```text
The Python Agent watches the input folder, analyzes the image, generates the correction values, and creates a Lightroom apply request.

The Lightroom Plugin reads the apply request and applies the agent-generated correction values to the target image inside Lightroom Classic.
```

Therefore, the Lightroom plugin is not the folder watcher, not the AI analyzer, and not the orchestration engine. It is a Lightroom-side apply adapter.

---

## 2. Correct Role Definition

### 2.1 Lightroom Plugin Role

The Lightroom plugin must do only the following:

1. Load correctly inside Lightroom Classic.
2. Read apply request JSON files generated by the Python Agent.
3. Use `source_path` from the request to identify the target image.
4. Find the image in the Lightroom catalog or import/add it if necessary.
5. Apply the correction values generated by the Agent.
6. Write an apply result JSON file.
7. Report success or failure in a deterministic and inspectable way.

### 2.2 Lightroom Plugin Must Not Do

The Lightroom plugin must not perform these responsibilities:

1. It must not watch `F:\tonevyra_ai_agent\runtime\input` directly.
2. It must not scan the user image working folder.
3. It must not detect new photos by itself.
4. It must not run the AI model.
5. It must not analyze image content.
6. It must not create the correction plan.
7. It must not run the quality gate.
8. It must not make DB-level task decisions.
9. It must not orchestrate the full Tonevyra pipeline.
10. It must not auto-launch Lightroom Classic in T-019.

These responsibilities belong to the Python Agent or to later orchestration tasks.

## 3. Correct Architecture

### 3.1 Correct High-Level Flow

```text
User places image in working/input folder
→ Python Agent detects the image
→ Python Agent creates a task
→ Python Agent extracts metadata / preview
→ Python Agent analyzes the image
→ Python Agent generates correction values
→ Python Agent runs quality/planning rules
→ Python Agent writes Lightroom apply request JSON
→ Lightroom Plugin reads the request
→ Lightroom Plugin finds/imports the source image in Lightroom Classic
→ Lightroom Plugin applies the correction values
→ Lightroom Plugin writes apply result JSON
→ Python Agent reads result and records evidence
```

### 3.2 Component Responsibilities

| Component | Responsibility | Not Responsible For |
|---|---|---|
| Python Agent | Folder watching, task creation, image analysis, correction planning, quality gate, request creation | Lightroom internal API calls |
| Lightroom Plugin | Reading apply request, finding/importing target image, applying correction values, writing result | Folder watching, AI analysis, correction planning, quality scoring |
| Bridge Folder | File-based request/result exchange between Agent and Plugin | Business logic |
| Lightroom Classic | Catalog, import/find, Develop engine, preset/develop setting application | Agent orchestration |

## 6. Apply Request Contract

The Python Agent must create apply request JSON files for the Lightroom plugin.

Request directory:

```text
F:\tonevyra_ai_agent\runtime\bridge\lightroom_apply_requests
```

Example request:

```json
{
  "request_id": "lr_apply_001",
  "task_id": "task_001",
  "source_path": "F:\\tonevyra_ai_agent\\runtime\\input\\test.jpg",
  "operation": "apply_develop_settings",
  "develop_settings": {
    "Exposure": 0.30,
    "Contrast": 10,
    "Highlights": -20,
    "Shadows": 15,
    "Whites": 5,
    "Blacks": -5,
    "Vibrance": 8,
    "Saturation": 0,
    "Texture": 5,
    "Clarity": 3,
    "Dehaze": 2,
    "Sharpening": 25,
    "NoiseReduction": 10
  },
  "created_at": "2026-06-18T12:00:00Z"
}
```

### Required Fields

| Field | Required | Description |
|---|---:|---|
| `request_id` | Yes | Unique Lightroom apply request id |
| `task_id` | Yes | Tonevyra task id |
| `source_path` | Yes | Absolute path to the target image |
| `operation` | Yes | `apply_develop_settings` or future operation type |
| `develop_settings` | Yes | Agent-generated correction values |
| `created_at` | Yes | Request creation timestamp |

### Critical Rule

The `source_path` is how Lightroom knows which image to work on.

The plugin must not discover target images by scanning the input folder. It must use the `source_path` provided by the Agent.

## 8. How Lightroom Knows the Target Image

Lightroom Classic knows the target image through the request `source_path`.

The plugin must perform this logic:

```text
1. Read request.source_path.
2. Check whether a Lightroom catalog photo already exists for that path.
3. If found, use the existing LrPhoto object.
4. If not found, import/add the file to the catalog.
5. Apply correction values to that LrPhoto.
6. Write result JSON.
```

The user does not need to select the image in Lightroom. The selected photo is not the source of truth.

The source of truth is:

```text
request.source_path
```
